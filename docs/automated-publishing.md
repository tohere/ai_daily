# Hacker News AI 自动发布架构

本项目会从 Hacker News 官方 Firebase API 读取热门外部文章，使用星期天AI（Weekly Day AI）OpenAI 兼容接口生成中英文文章，并把生成结果写入 `src/data/generated-posts/`。

## 第 3 步：双语 AI 生成流程

本步骤新增了以下脚本：

- `scripts/article-pipeline/ai.mjs`：读取星期天AI配置，调用 `/chat/completions`，解析 JSON 响应。
- `scripts/article-pipeline/source-context.mjs`：抓取原文 HTML，删除脚本、样式和标签，只保留有限长度的纯文本。
- `scripts/article-pipeline/validate-generated.mjs`：严格校验模型输出，规范化 slug、标签和阅读时长，并强制写入披露文案。
- `scripts/article-pipeline/generate-article.mjs`：组合原文、模型和元数据，生成可提交的 JSON；文件使用排他创建，避免覆盖。
- `scripts/article-pipeline/dry-run-ai.mjs`：完全离线的模拟生成，不需要真实 API Key，也不会写入正式文章目录。

固定披露文案由程序写入，模型不能覆盖：

- 中文：本文使用星期天AI中转站大模型，基于 Hacker News 内容自动生成。
- English: This article was automatically generated by the Weekly Day AI gateway model using content from Hacker News.

页面渲染时会把“星期天AI”和“Weekly Day AI”链接到 [https://www.weekly-day.top/](https://www.weekly-day.top/)。

## 本地验证

复制 `.env.example` 为 `.env` 后填写真实配置。真实密钥只放在本地环境或 GitHub Actions Secrets，不能提交到仓库。

`@bash
pnpm test:content
pnpm content:ai:dry-run
pnpm build
`@

`content:ai:dry-run` 使用内置 fixture 和模拟接口，只用于验证请求体、原文清理、双语 JSON 校验、固定披露文案及文件命名。

## 生成结果格式

正式文章文件命名为：

`@text
src/data/generated-posts/YYYY-MM-DD-hn-<item-id>.json
`@

JSON 包含 `source`、`generation` 与 `post` 三部分。`source.hnId` 是永久去重键；`generation.providerUrl` 固定为 `https://www.weekly-day.top/`；`post.disclosure` 必须使用程序内置的中英文文案。

## 运行约定

- 默认每天生成 2 篇文章，数量由 `DAILY_ARTICLE_COUNT` 控制。
- 默认筛选 Hacker News 前 50 个热门条目，要求分数至少 50、评论至少 10 条。
- 如果原文无法抓取，流程会使用 Hacker News 元数据继续生成，但提示词会明确要求模型降低断言强度。
- 单篇失败不会覆盖已有文件；完整生成和校验成功后才写入目标目录。
- 第 5 步会把抓取、生成、提交、Astro 构建和 Cloudflare Pages 部署串接到 GitHub Actions。
